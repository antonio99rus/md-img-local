# Код-ревью `md-img-local.py`

Дата: 2026-10-28

Проверены `md-img-local.py`, тесты, `pyproject.toml` и README. Текущий набор тестов проходит.
Ниже — только замечания и план исправлений, код не менялся. Часть проблем воспроизведена
локальными прогонами (это отмечено в тексте).

---

## Критичные

### 1. Замена выполняется по всему тексту, включая код и комментарии
**Что не так.** Все четыре regex (`INLINE_IMAGE_RE`, `HTML_IMG_RE`, `REF_IMAGE_RE`, `REF_DEF_RE`,
строки 20–33) применяются к полному тексту (533–535, 550). Проверено: картинки внутри
fenced-блока ```` ``` ````, inline-code и HTML-комментария `<!-- ... -->` скачиваются и
переписываются. Также переписывается экранированный `\![...]`, а reference-определение
с отступом в 4 пробела (код-блок по CommonMark) может быть удалено.

**Почему это проблема.** Это порча пользовательского документа: примеры кода и документация
меняются, причём без ведома пользователя. Плюс лишние сетевые запросы к URL, которые
картинками не являются.

**Как исправить.** Разбирать Markdown парсером (`markdown-it-py`/`mistune`) и работать
с AST + source map. Если оставаться на regex — предварительно маскировать fenced-блоки,
inline-code, HTML-комментарии и экранированные `!` плейсхолдерами, а после замен вернуть
обратно. Обязательно регрессионные тесты на каждый случай.

### 2. Пути с пробелами и спецсимволами ломают Markdown/HTML
**Что не так.** `relative`/`local` вставляется в ссылку как есть (402–403, 499, 510, 531).
Проверено: `--media "my images"` даёт `![a](my images/a-....png)`. Аналогично сломаются
пути с `)`, `#`, `?`, `&`, `<`, `>`, а в HTML — с кавычками.

**Почему это проблема.** Документ становится синтаксически невалидным, картинка не
отображается. Для HTML возможен выход за пределы атрибута.

**Как исправить.** Percent-encode путь для Markdown (`quote(..., safe="/")`) либо оборачивать
destination в `<...>`; для HTML-атрибутов применять `html.escape(..., quote=True)`.
Добавить тесты с пробелами, скобками, `#`, `?`, юникодом и кавычками.

### 3. Бэкап и запись: `in-place` по умолчанию (решение принято)
**Уточнение.** Переименование исходника в `.orig` — сознательное решение, чтобы сохранить
исходный inode. Но текущий код меняет inode *рабочего* файла: после `replace` inode `A`
находится у `.orig`, а `write_text` создаёт по рабочему пути новый inode `B`. Если цель —
сохранить inode именно рабочего пути (hardlinks, ACL/ADS, file ID, bind mount, file
watchers), текущая схема её не достигает. Дополнительно существующий `.orig`
перезаписывается, а новый рабочий файл теряет mode/ACL.

**Фундаментальное ограничение.** На POSIX нет переносимой атомарной операции «заменить
содержимое, сохранив inode»: `rename`/`os.replace` атомарно меняет directory entry и,
значит, inode; запись in place inode сохраняет, но не атомарна для читателей и при падении.
Поэтому выбор — atomic replace без сохранения inode либо in-place с журналом и
восстановлением. «Безопасный» во втором случае означает «восстановимый», а не «атомарный».

**Решение (2026-10-28): вариант C, `in-place` по умолчанию.**

- `--write-mode {in-place,atomic}`, по умолчанию `in-place`.
- `in-place` сохраняет inode рабочего файла, hardlinks, mode/ACL/ADS и File ID на Windows.
  Цена — отсутствие атомарности и необходимость journal/восстановления.
- `atomic` — opt-in для максимальной защиты от повреждений: temp в том же каталоге →
  `fsync` → `shutil.copystat` → `os.replace(temp, source)`. Inode при этом меняется.
- Бэкап в обоих режимах — независимая копия, не `rename` и не hardlink.
- Существующий `.orig` ротируется (`.orig.1`, timestamp) или требуется `--force`;
  молчаливая перезапись запрещена.
- `--no-backup` в `in-place` допускается только с `--force`: иначе нет источника
  восстановления. В `atomic` режиме предупреждение достаточно.
- README/README-EN-US обновлять одновременно с реализацией, а не сейчас: они описывают
  текущую версию 1.2.0, где такого поведения ещё нет.

**Режим по умолчанию: `in-place` с восстановлением.**
1. `fd = os.open(path, os.O_RDWR)` без `O_TRUNC`; `fstat` → `(dev, ino, size, mtime_ns)`.
2. Взять advisory lock (`fcntl.flock` / `msvcrt.locking`), понимая, что чужие процессы
   могут его игнорировать.
3. Подготовить полный новый контент во временном файле в том же каталоге, `fsync`.
4. Сделать независимый бэкап: копия из fd в `.orig.tmp`, `fsync`, затем
   `os.replace(.orig.tmp, .orig)`; при существующем `.orig` — ротация/`--force`.
5. Повторно `fstat`: если `size`/`mtime_ns`/`ino` изменились — прервать, source не трогать.
6. `lseek(fd, 0)`, записать все байты, `ftruncate(fd, len)`, `fsync(fd)`.
7. Прочитать из fd и сравнить hash с подготовленным; при несовпадении — восстановить
   из `.orig` и сообщить.
8. Держать journal/`.new` до успешной проверки; на старте при наличии journal не
   продолжать молча, а предлагать восстановление. Удалить temp, снять lock.

Ограничения `in-place`: читатели могут увидеть частичное содержимое; при падении
посреди записи файл повреждён до восстановления; без бэкапа/журнала это небезопасно.
На Windows `os.replace` часто падает, если файл открыт другим процессом, — `in-place`
там даже удобнее; блокировки и `fsync` на SMB/NFS могут не работать как ожидается.
Автовыбор по `st_nlink > 1` не используется: он не покрывает file watchers и bind mounts,
поэтому режим задаётся явно.

**Тесты.** `st_ino`/`st_dev` до и после; hardlink видит новый контент; mode 600/ACL
сохраняются; инъекция падения посреди `write`/`ftruncate` с восстановлением из `.orig`;
обнаружение конкурентной записи; ротация `.orig`; symlink; read-only каталог;
`--write-mode atomic` меняет inode, но оставляет исходник целым при сбое.

### 4. Скачивание без ограничений по размеру и типу
**Что не так.** `session.get(...)` + `response.content` (392–401): тело целиком читается
в память, нет `stream`, лимита размера, проверки `Content-Length`/`Content-Type`,
ограничения редиректов. Сохраняется любое содержимое.

**Почему это проблема.** DoS по памяти и диску. Под видом картинки можно скачать
HTML/архив/исполняемый файл; при публикации каталога `media` возможен stored XSS
через `.html`/`.svg`.

**Как исправить.** `stream=True`, `iter_content` с жёстким лимитом (например, 20 МБ,
настраиваемо), проверка `Content-Type` по allowlist `image/*`, проверка `Content-Length`,
лимит редиректов, отмена при превышении. Отдельно решить политику по SVG
(запрет или санитайз).

### 5. Пароль прокси утекает в сообщение об ошибке
**Что не так.** В `proxy_unsupported` подставляется `value=value` (285–291). Для
`--proxy=ftp://user:secret@host:21` секрет попадает в stderr целиком. `proxy_invalid` тоже
может эхоить часть URL.

**Почему это проблема.** Секрет оказывается в логах CI, терминале, тикетах. README при этом
обещает, что пароль не печатается.

**Как исправить.** Никогда не печатать raw-URL. Маскировать userinfo до форматирования
(best-effort `mask_proxy`), в сообщении показывать только схему/хост. Добавить тест:
`secret` не встречается в stderr.

### 6. SSRF: любой URL из документа, включая внутреннюю сеть
**Что не так.** Проверяется только `http(s)://`, но не хост. Разрешены `localhost`,
`127.0.0.1`, приватные диапазоны, `169.254.169.254`. Редиректы включены по умолчанию,
проверки после редиректа нет.

**Почему это проблема.** Недоверенный `.md` в CI или на машине разработчика позволяет ходить
во внутренние сервисы, читать метаданные облака и складывать ответы в `media`.

**Как исправить.** Резолвить хост и отклонять loopback/private/link-local/multicast/
unspecified; проверять каждый redirect (ручной цикл или adapter); добавить `--allow-private`
для осознанных сценариев. Для защиты от DNS rebinding — подключение к уже resolved IP
с корректным `Host` (сложнее, можно вторым этапом). Задокументировать модель доверия.

### 7. Запись следует симлинкам в каталоге `media`
**Что не так.** `destination.write_bytes(...)` (401) пишет по пути, имя которого
предсказуемо (`sha256(url)`). Если каталог доступен другим пользователям, можно заранее
создать симлинк и перезаписать произвольный файл.

**Почему это проблема.** CWE-59: локальная порча файлов.

**Как исправить.** Писать в уникальный временный файл в `media` и делать `os.replace`
(он заменит саму ссылку), либо открывать через `os.open` с `O_CREAT|O_EXCL|O_WRONLY`
(+`O_NOFOLLOW`, где поддерживается).

## Высокие

### 8. Код возврата всегда 0, ошибки идут в stdout, исключения не перехвачены
**Что не так.** `main()` ничего не возвращает, `failed` не влияет на exit code (558–563).
Ошибки скачивания печатаются в stdout (406–411). Ряд ошибок не обработан: проверено —
`--media` указывает на файл → `FileExistsError`; файл в cp1251 → `UnicodeDecodeError`;
`--media` на другом диске → `ValueError: path is on mount...` (402).

**Почему это проблема.** CI и скрипты считают запуск успешным, даже если не скачалось ничего.
Вместо понятной локализованной ошибки — трейсбек.

**Как исправить.** Возвращать/пробрасывать код: 0 — успех, 1 — были ошибки скачивания,
2 — ошибка конфигурации. Ошибки — в stderr, отчёт — в stdout. Общий
`try/except (OSError, UnicodeError, ValueError)` с понятным сообщением; для `relpath` —
fallback/явная ошибка про разные диски.

### 9. Кодировка и переводы строк меняются
**Что не так.** Чтение и запись строго в UTF-8 (485, 556), `read_text`/`write_text`
с `newline=None`. Проверено: LF-файл на Windows после обработки целиком стал CRLF;
cp1251 падает с трейсбеком.

**Почему это проблема.** Огромные diff’ы из-за смены окончаний строк, невозможность
обработать старые/локальные файлы, потеря исходных байтов.

**Как исправить.** Читать байты, определять BOM (`utf-8-sig`, UTF-16) и сохранять исходные
окончания строк (`newline=""` или работа с bytes). Добавить `--encoding` либо понятную
ошибку при неудачном декодировании. Тесты: LF, CRLF, UTF-8 BOM, cp1251.

### 10. Возможности regex-парсера ограничены и местами эвристичны
**Что не так.** Не поддерживаются protocol-relative `//cdn/...`, `srcset`, `<source>`,
unquoted `src`, многострочные теги, URL с `)` вне `<...>`, вложенные `]` в alt, title
в `(...)`. При инлайне reference-картинки теряется title из определения. Дубликаты
определений переопределяются «последний побеждает», хотя по CommonMark — первый. Удаление
определений (537–550) ищет подстроку `[key]` по всему документу и компилирует regex
на каждое определение.

**Почему это проблема.** Часть ссылок молча не обрабатывается, часть — обрабатывается
неверно; эвристика даёт ложные срабатывания, а компиляция regex на каждое определение —
лишняя работа на больших файлах.

**Как исправить.** Перейти на AST-парсер и точный учёт использований. Если regex
остаётся — явно задокументировать ограничения, добавить `//`, `srcset`, unquoted `src`,
собирать usage из разобранных узлов, а не поиском подстроки.

### 11. TLS-модель противоречива: `truststore` + `certifi`
**Что не так.** `truststore.inject_into_ssl()` вызывается на импорте (17–18), а каждый
запрос идёт с `verify=certifi.where()` (394). Явный `verify` отключает
`REQUESTS_CA_BUNDLE`/`SSL_CERT_FILE`; README обещает проверку по `certifi`, но одновременно
тянет `truststore`. Инъекция на импорте меняет SSL глобально для всего процесса
(включая тесты).

**Почему это проблема.** Непонятно, какой trust store используется; корпоративный CA
не подключить; лишняя зависимость и побочный эффект при импорте.

**Как исправить.** Выбрать одну модель: либо только `truststore` (инъекция в `main()`
до создания сессии, `verify=True`, убрать `certifi`), либо только `certifi` (убрать
`truststore`, добавить `--ca-bundle`/поддержку env). Обновить README и добавить тест
с собственным CA.

## Средние

### 12. Дубликаты из-за fragment и отсутствия нормализации URL
**Что не так.** Кэш и хэш имени строятся по полному URL (378, 385, 412).
`https://x/a.png#one` и `https://x/a.png#two` дадут два запроса и два файла, хотя
fragment на сервер не отправляется.

**Почему это проблема.** Лишние запросы и файлы, завышенный счётчик «найдено».

**Как исправить.** Канонизировать URL перед кэшированием: убрать fragment, привести
схему/хост к нижнему регистру, убрать порты по умолчанию. Query не сортировать
(меняет семантику).

### 13. Имена файлов и расширения не ограничены
**Что не так.** `filename_for_url` (353–359) не ограничивает длину stem → возможен
`ENAMETOOLONG`; расширение берётся из URL даже если сервер отдал HTML (`.php`, `.html`);
`mimetypes` зависит от ОС; хэш 10 hex-символов — 40 бит; SVG сохраняется как активный
контент.

**Почему это проблема.** Сбои на длинных URL, неверные типы файлов, риск XSS при публикации
`media`, редкие коллизии имён.

**Как исправить.** Обрезать stem до 50–80 символов, выбирать расширение по allowlist
из `Content-Type`, использовать фиксированную таблицу MIME вместо `mimetypes`, увеличить
хэш до 16+ символов, определить политику по SVG.

### 14. Логи раскрывают токены и допускают terminal injection
**Что не так.** Полный URL печатается в `[OK]`/`[ERROR]` (405, 408, 411). URL
с pre-signed query или userinfo попадает в логи; управляющие символы (ESC/OSC) из URL
могут воздействовать на терминал.

**Почему это проблема.** Утечка подписанных токенов в CI-логах и манипуляция терминалом.

**Как исправить.** Редактировать userinfo и чувствительные query-параметры, обрезать query,
экранировать control chars. Полный URL показывать только по `--verbose`.

### 15. Вывод на Windows при перенаправлении может быть нечитаемым
**Что не так.** Проверено: при запуске в PowerShell без `PYTHONIOENCODING` русские
сообщения выводятся как `�������`. Тесты это маскируют, потому что `run_cli` выставляет
`PYTHONIOENCODING=utf-8`.

**Почему это проблема.** Нечитаемые логи, потенциальный `UnicodeEncodeError` при
перенаправлении вывода.

**Как исправить.** В начале `main()` переконфигурировать `sys.stdout`/`sys.stderr`
(`encoding="utf-8", errors="replace"`) с fallback для старых Python. Добавить тест
без `PYTHONIOENCODING`.

### 16. Локализация неполная и местами расходится
**Что не так.** `LocalizedArgumentParser.error` (262–265) переводит только префикс, сами
сообщения argparse остаются английскими. `--lang=de` при русской локали даёт английскую
ошибку, потому что pre-scan не нормализует «de». `add_usage` игнорирует переданный
`prefix`; `start_section` хардкодит заголовки. `language_from_argv` не понимает сокращения
(`--lan`), повторный `--lang`, значения, съеденные другим аргументом; при этом второй
`set_language` после `parse_args` избыточен.

**Почему это проблема.** Смешанный язык в одном сообщении и непредсказуемая справка.

**Как исправить.** Сделать pre-parser для `--lang` с теми же правилами, что у argparse;
добавить маппинг/перевод ошибок argparse; honor `prefix`; покрыть тестами смешанные случаи.

### 17. Глобальное состояние и монолитный `main()`
**Что не так.** Язык хранится в модульной переменной `_language` (150, 221–225). `main()` —
~150 строк с вложенными функциями, которые мутируют `found_urls`, `replaced_ref_keys`,
`new_text`. `Downloader.localize` смешивает сеть, файловые операции, печать и счётчики
(366–413).

**Почему это проблема.** Сложно тестировать и переиспользовать, тесты зависят от порядка,
появление потоков сломает глобальный язык. Читаемость страдает.

**Как исправить.** Вынести перевод в `Translator`/`ContextVar`. Разбить `main` на
`parse_args`, `rewrite(text, downloader) -> RewriteResult`, `report(result)`; статистику —
в dataclass; печать инжектить как `echo`/reporter.

### 18. Настройки HTTP и последовательность запросов
**Что не так.** `timeout=30` одним числом (392–396), нет retry/backoff, запросы строго
последовательны, `verify` передаётся в каждый вызов, `session.close()` не в `finally` (563).

**Почему это проблема.** Медленно на больших документах, транзиентные сбои не переживаются,
при исключении сессия не закрывается.

**Как исправить.** `timeout=(connect, read)`, `HTTPAdapter(max_retries=Retry(...))`,
`session.verify` вместо аргумента в каждом запросе, `with session:`/try-finally.
Параллелизм — опционально и с сессией на поток (requests.Session не thread-safe).

### 19. Каталог `media` создаётся слишком рано и без обработки ошибок
**Что не так.** `media_dir.mkdir(parents=True, exist_ok=True)` вызывается до чтения/анализа
файла (473–478). Если `--media` указывает на файл — `FileExistsError`; пустой каталог
создаётся даже когда картинок нет; `~` не раскрывается, а относительный `--media`
считается от CWD, а не от `.md`.

**Почему это проблема.** Мусорные каталоги, неочевидное поведение, трейсбеки.

**Как исправить.** Валидировать/создавать каталог после сбора URL или лениво;
`.expanduser()`; ловить `OSError` и выдавать локализованную ошибку; явно задокументировать
базу относительного пути.

### 20. Захардкоженный браузерный User-Agent и дублирование версии
**Что не так.** UA Chrome 138 захардкожен (38), хотя это CLI. Версия продублирована
в `VERSION` и `pyproject.toml` (35; pyproject 3) и синхронизируется тестом.

**Почему это проблема.** Маскировка под браузер может нарушать ToS сайтов и быстро
устаревает; дублирование версии — лишняя точка отказа.

**Как исправить.** Сделать UA конфигурируемым (`--user-agent`) или честным по умолчанию;
версию оставить в одном месте либо оставить тест как защиту от рассинхрона, но
зафиксировать это решение.

## Тесты и сборка

### 21. Тесты не покрывают самые рискованные сценарии
**Что не так.** Нет тестов на: код-блоки/комментарии/экранирование, пробелы и скобки
в путях, CRLF/LF и cp1251, лимиты размера/типа, коды возврата, разные диски,
`--media`-файл, симлинки, утечку пароля в stderr, control chars в URL. Заявленное
«full code coverage» — это строчное покрытие, а не поведенческое.

**Почему это проблема.** Именно эти пути ломаются, и регрессии не будут замечены.

**Как исправить.** По каждому пункту выше добавить отдельный регрессионный тест;
для потокового скачивания расширить `FakeResponse` (`iter_content`, `headers`,
`status_code`).

### 22. Тесты требуют Python 3.11, а проект обещает 3.10+
**Что не так.** `tests/test_cli.py:5` и `tests/test_docs.py:3` импортируют `tomllib`
(появился в 3.11), при этом `pyproject.toml:6` разрешает 3.10.

**Почему это проблема.** На Python 3.10 тесты падают, хотя приложение должно работать.

**Как исправить.** Добавить `tomli; python_version < "3.11"` в dev-зависимости
с fallback-импортом либо поднять `requires-python` до 3.11 и обновить README.

### 23. Тесты местами нестабильны или зависят от окружения
**Что не так.** `free_port()` (test_integration.py:85, socks5_proxy.py:107) — классический
TOCTOU: порт может занять кто-то другой. Тест недоступного прокси упадёт, если не установлен
PySocks (сработает `ensure_socks_support`, а не сетевая ошибка). `Socks5Proxy` имеет
таймауты релея и потоки-обработчики, которые могут влиять на teardown. `test_docs`
проверяет наличие подстрок, а не смысл.

**Почему это проблема.** Флаки в CI и ложные падения на чистом окружении.

**Как исправить.** Для «недоступного» прокси использовать адрес из TEST-NET или явно
мокать `ensure_socks_support`; добавить `importorskip`; аккуратнее останавливать
обработчики; проверять документацию по ключевым утверждениям (флаги, версия, ссылки).

### 24. Тесты не проверяют реальную сборку сессии
**Что не так.** `conftest.py` подменяет `build_session`, поэтому `main()` никогда не проходит
через реальную настройку `trust_env`/`proxies`/`verify`; это проверяется только
юнит-тестами. Утверждения `timeout == 30` и `verify == certifi.where()` жёстко привязаны
к реализации.

**Почему это проблема.** Изменение TLS/прокси-логики может пройти незамеченным.

**Как исправить.** Оставить юнит-тесты как контракт, но добавить один интеграционный тест
на `build_session` (или через `main` с временным HTTP-сервером) и проверку, что
env-переменные прокси не перебивают `--proxy`.

## План работ по приоритетам

1. **Регрессионные тесты** на порчу документа: код-блоки, inline-code, комментарии, `\!`,
   пробелы/скобки в путях, LF/CRLF, cp1251.
2. **Целостность документа**: маскировка/парсер для кода, экранирование путей,
   `--write-mode {in-place,atomic}` с `in-place` по умолчанию, journal/восстановление,
   ротация `.orig`, сохранение inode/прав.
3. **Безопасность загрузки**: лимит размера, allowlist `Content-Type`, отказ от следования
   симлинкам, SSRF-политика, маскирование секретов в логах.
4. **Надёжность CLI**: коды возврата, stderr для ошибок, обработка
   `OSError`/`UnicodeError`/`ValueError`, `session` в `finally`, кодировка stdout.
5. **TLS и локализация**: выбрать `truststore` или `certifi`, убрать import-side-effect,
   доделать перевод ошибок argparse, убрать глобальный `_language`.
6. **Рефакторинг**: разбить `main`, вынести `rewrite`/`report`, инжектить вывод и перевод.
7. **Парсер и производительность**: перейти на AST-парсер, канонизировать URL, добавить
   retry/таймауты, при необходимости — аккуратный параллелизм.
8. **Инфраструктура**: CI-матрица 3.10–3.13, `ruff`/`mypy`, обновление README/Plan.md
   под фактическое поведение (бэкап, TLS, лимиты).
