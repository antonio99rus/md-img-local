# md-img-local

[English version](README-EN-US.md)

Скачивает изображения из Markdown-файла в `media/` (или указанный каталог) и заменяет ссылки на локальные.

Поддерживаются три синтаксиса ссылок:

- inline: `![alt](https://example.com/img.png "title")`, в том числе в угловых скобках `<url>`;
- reference-style: `![alt][id]` + `[id]: https://example.com/img.png`; при дубликате побеждает первое определение, его title сохраняется;
- HTML: `<img src="https://example.com/img.png" ...>` с `src` в кавычках или без, а также `srcset` у `<img>` и `<source>`.

Protocol-relative URL (`//cdn.example/img.png`) трактуются как HTTPS. Изображения внутри fenced-блоков, inline-кода, HTML-комментариев и экранированные `\![...]` не изменяются. Одинаковый канонический URL скачивается один раз; локальные ссылки не трогаются.

## Требования

- Python 3.10+;
- [`requests`](https://pypi.org/project/requests/) с дополнением `socks` (нужно для SOCKS-прокси);
- [`truststore`](https://pypi.org/project/truststore/) — проверка TLS по хранилищу сертификатов операционной системы.

## Установка

Через `uv` (зависимости описаны в `pyproject.toml`):

```bash
uv sync
uv run python md-img-local.py --help
```

Через `pip`:

```bash
pip install "requests[socks]" truststore
```

## Использование

```bash
python md-img-local.py <файл.md> [параметры]
```

| Аргумент | Описание |
| --- | --- |
| `<файл.md>` | Исходный Markdown-файл (обязательный). |
| `--media КАТАЛОГ` | Каталог для изображений. По умолчанию `media/` рядом с Markdown-файлом. Относительный путь отсчитывается от каталога Markdown-файла; `~` раскрывается. |
| `--no-backup` | Не создавать резервную копию `файл.md.orig`. В режиме `in-place` дополнительно требует `--force`; в режиме `atomic` допускается без него. |
| `--force` | Перезаписать существующий `файл.md.orig` вместо ротации, разрешить `--no-backup` в `in-place` и отбросить оставшийся журнал записи. |
| `--write-mode in-place\|atomic` | Способ записи результата. `in-place` — по умолчанию, сохраняет inode и hardlinks; `atomic` заменяет файл через временный. |
| `--allow-private` | Разрешить скачивание с приватных, loopback- и link-local адресов. По умолчанию запрещено для защиты от SSRF. |
| `--proxy URL` | Скачивать через прокси, например `socks5://127.0.0.1:3066`. Явный прокси перекрывает переменные окружения. |
| `--user-agent STRING` | Заголовок `User-Agent` для скачивания. По умолчанию `md-img-local/<версия>`. |
| `--lang en\|ru` | Язык сообщений и справки. По умолчанию — локаль системы. |
| `--verbose` | Печатать полные URL в логах вместо замаскированных. Пароли прокси по-прежнему скрываются. |
| `--version` | Показать версию программы. |
| `-h, --help` | Показать справку и выйти. |

Примеры:

```bash
# Обычный запуск
python md-img-local.py note.md

# Свой каталог для изображений
python md-img-local.py note.md --media "my images"

# Атомарная запись без бэкапа
python md-img-local.py note.md --write-mode atomic --no-backup

# Через SOCKS5-прокси (DNS-имена резолвятся локально)
python md-img-local.py note.md --proxy=socks5://127.0.0.1:3066

# Через SOCKS5-прокси, DNS-имена резолвит прокси
python md-img-local.py note.md --proxy=socks5h://127.0.0.1:3066
```

## Как это работает

1. Markdown-файл читается как байты. Поддерживаются UTF-8, UTF-16 и UTF-32 (с BOM); исходные BOM и переводы строк сохраняются.
2. Код-блоки, inline-код, HTML-комментарии и экранированный `!` маскируются, чтобы примеры не переписывались и не скачивались.
3. Ссылки на изображения собираются и канонизируются: fragment удаляется, схема и хост приводятся к нижнему регистру, порты по умолчанию отбрасываются. Query-строка сохраняется; protocol-relative URL трактуются как HTTPS.
4. Каждое уникальное изображение скачивается в `media/`; каталог создаётся лениво при первом успешном скачивании.
5. Ссылки заменяются на POSIX-пути относительно Markdown-файла. Пробелы и спецсимволы percent-кодируются для Markdown и HTML; дескрипторы `srcset` (`1x`, `480w` и т. п.) сохраняются.
6. Создаётся резервная копия (если не отключена), затем результат записывается выбранным способом.
7. В stdout выводится отчёт: сколько уникальных изображений найдено, скачано и сколько было ошибок.

При ошибке скачивания ссылка остаётся как была, обработка продолжается.

### Правила скачивания

- Максимальный размер: 20 МиБ на изображение; проверяются и `Content-Length`, и потоковое тело.
- Разрешённые типы: PNG, JPEG, GIF, WebP, BMP, TIFF, AVIF и ICO. SVG и неизвестные типы отклоняются.
- Редиректы выполняются вручную, не более 5; каждый новый адрес проверяется заново.
- Приватные, loopback-, link-local-, reserved-, multicast- и unspecified-адреса отклоняются, если не указан `--allow-private`.
- Таймаут соединения — 10 секунд, чтения — 30 секунд. GET-запросы повторяются дважды при `429`, `500`, `502`, `503` и `504`.
- Имена файлов — `stem-<sha256(url)[:16]><ext>`. Stem очищается и ограничивается 80 символами; расширение берётся из `Content-Type` ответа, а не из URL.

### Бэкап и режимы записи

- Бэкап — независимая копия `файл.md.orig`. Существующая копия ротируется в `файл.md.orig.1`, `файл.md.orig.2` и так далее. С `--force` существующий `файл.md.orig` перезаписывается.
- `in-place` (по умолчанию) сохраняет inode, hardlinks, права, ACL и альтернативные потоки данных. Сначала пишутся журнал и промежуточная копия; конкурентное изменение обнаруживается, результат сверяется по хэшу, а неудачная запись восстанавливается из бэкапа. Читатели могут ненадолго увидеть частичное содержимое.
- `atomic` пишет временный файл в том же каталоге, вызывает `fsync`, копирует метаданные и заменяет исходник через `os.replace`. Результат атомарен, но inode меняется, а hardlinks отвязываются.
- После успешного запуска бэкап `.orig` остаётся; удаляйте его вручную, когда он больше не нужен.

## Вывод и коды возврата

- `[OK]`, `[BACKUP]` и итоговый отчёт идут в stdout; сообщения `[ERROR]` и ошибки конфигурации — в stderr.
- Код `0` — успех.
- Код `1` — хотя бы одно изображение не удалось скачать или сохранить.
- Код `2` — ошибка конфигурации, входных данных или локального ввода-вывода (нет файла, неверный прокси, неподдерживаемая кодировка, ошибка записи и т. п.).

URL в логах по умолчанию маскируются: учётные данные и чувствительные query-параметры заменяются, управляющие символы нейтрализуются. С `--verbose` печатаются полные URL; управляющие символы по-прежнему нейтрализуются, а пароли прокси скрываются всегда.

## Прокси

- Поддерживаемые схемы: `http`, `https`, `socks4`, `socks4a`, `socks5`, `socks5h`.
- Порт обязателен: `socks5://127.0.0.1:3066` (без порта будет ошибка).
- `socks5://` резолвит имена локально, `socks5h://` — на стороне прокси. Если локальный DNS не видит нужные имена, используйте `socks5h`.
- Для SOCKS-прокси нужен PySocks: он ставится вместе с `requests[socks]` (через `uv sync` — автоматически). Без него программа сразу сообщит об ошибке.
- Явно указанный `--proxy` имеет приоритет над переменными окружения `HTTP_PROXY`, `HTTPS_PROXY`, `NO_PROXY` — при использовании флага они игнорируются. Без флага переменные окружения работают как обычно.
- Пароль в адресе прокси не выводится: в логах он заменяется на `***`.
- При ошибке соединения в сообщении появляется подсказка, что прокси может быть недоступен.

## TLS

Сертификаты проверяются всегда. `truststore` использует хранилище сертификатов операционной системы, поэтому корпоративные прокси с инспекцией TLS работают, если их CA установлен в системе. Сервер с недоверенным сертификатом отклоняется.

## Локализация

Сообщения и справка (`--help`) выводятся на русском или английском языке. Язык выбирается в таком порядке:

1. `--lang ru|en`;
2. переменная окружения `MD_IMG_LOCAL_LANG`;
3. `LC_ALL`, `LC_MESSAGES`, `LANG`, `LANGUAGE`;
4. локаль ОС (в Windows — язык интерфейса);
5. если ничего не подошло — английский.

```bash
python md-img-local.py note.md --lang=ru
MD_IMG_LOCAL_LANG=ru python md-img-local.py note.md
```

Английская документация — в [README-EN-US.md](README-EN-US.md).

## Известные ограничения

- Ссылки разбираются регулярными выражениями. Кандидаты `srcset` делятся по запятым, поэтому URL с незакодированной запятой не поддерживается; `<source src>` (в отличие от `<source srcset>`) и разметка `<picture>` вне `srcset` не обрабатываются.
- Скачиваются все удалённые кандидаты `srcset`, включая все указанные разрешения.
- Изображения скачиваются последовательно.

```bash
uv sync                # заодно поставит dev-зависимости (pytest, pytest-cov, ruff)
```
