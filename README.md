# md-img-local

Скачивает изображения из Markdown-файла в `media/` (или указанный каталог) и заменяет ссылки на локальные.

Поддерживаются три синтаксиса ссылок:

- inline: `![alt](https://example.com/img.png "title")`, в том числе в угловых скобках `<url>`;
- reference-style: `![alt][id]` + `[id]: https://example.com/img.png`;
- HTML: `<img src="https://example.com/img.png" ...>`.

Одинаковые URL скачиваются один раз. Локальные ссылки не изменяются.

## Требования

- Python 3.10+;
- зависимости: [`requests`](https://pypi.org/project/requests/) (с дополнением `socks` — оно нужно для работы через SOCKS-прокси), [`certifi`](https://pypi.org/project/certifi/), [`truststore`](https://pypi.org/project/truststore/).

## Установка

Через `uv` (зависимости описаны в `pyproject.toml`):

```bash
uv sync
uv run python md-img-local.py --help
```

Через `pip`:

```bash
pip install "requests[socks]" certifi truststore
```

## Использование

```bash
python md-img-local.py <файл.md> [--media КАТАЛОГ] [--no-backup] [--proxy URL]
```

| Аргумент | Описание |
| --- | --- |
| `<файл.md>` | Исходный Markdown-файл (обязательный). |
| `--media КАТАЛОГ` | Каталог для изображений; по умолчанию `media/` рядом с Markdown-файлом. |
| `--no-backup` | Не создавать резервную копию `файл.md.orig`. |
| `--proxy URL` | Скачивать через прокси, например `socks5://127.0.0.1:3066`. |
| `--version` | Показать версию программы. |

Примеры:

```bash
# Обычный запуск
python md-img-local.py note.md

# Через SOCKS5-прокси (DNS-имена резолвятся локально)
python md-img-local.py note.md --proxy=socks5://127.0.0.1:3066

# Через SOCKS5-прокси, DNS-имена резолвит прокси
python md-img-local.py note.md --proxy=socks5h://127.0.0.1:3066

# Через HTTP-прокси с авторизацией
python md-img-local.py note.md --proxy=http://user:password@proxy.example:3128
```

## Прокси

- Поддерживаемые схемы: `http`, `https`, `socks4`, `socks4a`, `socks5`, `socks5h`.
- Порт обязателен: `socks5://127.0.0.1:3066` (без порта будет ошибка).
- `socks5://` резолвит имена локально, `socks5h://` — на стороне прокси. Если локальный DNS не видит нужные имена, используйте `socks5h`.
- Для SOCKS-прокси нужен PySocks: он ставится вместе с `requests[socks]` (через `uv sync` — автоматически). Без него программа сразу сообщит об ошибке.
- Явно указанный `--proxy` имеет приоритет над переменными окружения `HTTP_PROXY`, `HTTPS_PROXY`, `NO_PROXY` — при использовании флага они игнорируются. Без флага переменные окружения работают как обычно.
- Пароль в адресе прокси не выводится: в логах он заменяется на `***`.
- При ошибке соединения в сообщении появляется подсказка, что прокси может быть недоступен.
- Прокси с подменой TLS-сертификатов (MITM) не поддерживается: проверка сертификатов идёт по `certifi`, поэтому для такого прокси потребуется собственный CA (пока не реализовано).

## Как это работает

1. Markdown-файл переименовывается в `файл.md.orig` (если не указан `--no-backup`).
2. Из текста собираются ссылки на изображения (inline, reference-style, HTML).
3. Каждое уникальное изображение скачивается в каталог `media/`; имя файла — `stem-<sha256(url)[:10]><ext>`.
4. Ссылки в тексте заменяются на локальные пути относительно Markdown-файла.
5. Результат записывается обратно в исходный файл; в stdout выводится отчёт: сколько изображений найдено, скачано и сколько ошибок.

При ошибке скачивания ссылка остаётся как была, обработка продолжается.

## Тесты

```bash
uv sync                # заодно поставит dev-зависимости (pytest, pytest-cov)
uv run pytest          # запуск тестов
uv run pytest --cov    # запуск с отчётом о покрытии
```

Без `uv`: `pip install pytest pytest-cov`, затем `pytest`.

Тесты лежат в `tests/`: проверки разбора прокси, скачивания, замены ссылок (inline, reference-style, HTML), резервных копий, CLI и интеграционные сценарии с локальным HTTP-сервером и SOCKS5-прокси.
