# План: программа `md-img-local.py`

План *Big Pickle*. Текущая версия — 1.1.0.

**Язык:** Python, зависимости: `requests[socks]` (стандарт проекта — `uv`, описание в `pyproject.toml`).

## CLI
```
python md-img-local.py <файл.md> [--media каталог] [--no-backup] [--proxy URL]
```
- `<файл.md>` — единственный обязательный аргумент.
- `--media` — каталог для картинок, по умолчанию `media/` рядом с файлом.
- Флаг `--no-backup` (опционально) — пропустить создание `.orig`.
- `--proxy` (опционально) — прокси для скачивания, например `--proxy=socks5://127.0.0.1:3066`; порт обязателен.
- `--version` — вывод версии.

## Алгоритм

1. **Резервная копия**: перед записью результата `файл.md` → `файл.md.orig` (конвенция уже используется в заметках). Если `.orig` уже существует — перезаписать (обновить).

2. **Сбор ссылок** (три синтаксиса):
   - Inline: `![alt](<url> | url "title")`
   - Reference-style: `[id]: <url>` — сначала собрать определения ссылок в словарь, затем находить `![alt][id]` и подставлять URL; `[id]: url` в итоге удаляется из результата.
   - Инлайн-HTML: `<img src="url" ...>` (атрибут `src`, с учётом одинарных/двойных кавычек).

3. **Настройка HTTP-сессии**:
   - Один `requests.Session` на весь запуск (пул соединений, особенно важно через прокси).
   - `User-Agent`, `verify=certifi.where()`, таймаут 30 с.
   - `--proxy`: адрес проверяется до начала работы (схема из `http`, `https`, `socks4`, `socks4a`, `socks5`, `socks5h`; обязательны хост и порт); схема нормализуется в нижний регистр.
   - Для socks-схем проверяется наличие PySocks (`requests[socks]`), иначе понятная ошибка с кодом 2.
   - Прокси задаётся для `http` и `https`; при явном `--proxy` `Session.trust_env = False`, чтобы `HTTP_PROXY`/`HTTPS_PROXY`/`NO_PROXY` не перебивали флаг.
   - В лог прокси попадает с маскированным паролем (`user:***@host`).

4. **Скачивание** в `media/` с дедупликацией:
   - Имя: `stem-<sha256(url)[:10]><ext>` (как в `remote images to local-gpt.md`).
   - Расширение: из URL → иначе `Content-Type` → иначе `.bin`.
   - Одинаковый URL в любом из трёх синтаксисов — скачивается один раз (общий кэш URL→путь).

5. **Замена ссылок** на `media/файл` (posix-слэши, путь относительно файла .md):
   - inline: `![alt](media/файл "title")`
   - reference: заменяется на inline `![alt](media/файл)`, определение удаляется
   - `<img src="media/файл">`
   - Локальные пути (`./`, `media/`, файл без схемы) не трогаются.

6. **Обработка ошибок**: сбой скачивания — `[ERROR] url: причина`, ссылка остаётся как была; обработка продолжается. При использовании прокси в сообщение добавляется подсказка `(прокси <адрес> недоступен?)`.

7. **Запись**: результат пишется в исходный `файл.md` (после успешного полного прохода). В stdout — отчёт: найдено/скачано/не удалось, путь результата.

## Проверка
- Локальные ссылки не тронуты, дубликаты URL не качаются повторно.
- `--proxy` не влияет на разбор Markdown и замену ссылок.
- Проверены схемы `http`, `socks5`, `socks5h` (HTTP и HTTPS), ошибки валидации (нет порта, неизвестная схема), недоступный прокси, маскирование пароля.
