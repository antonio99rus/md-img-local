# План: программа `md-img-local.py`

План *Big Pickle*. Текущая версия — 1.2.0.

**Язык:** Python, зависимости: `requests[socks]` (стандарт проекта — `uv`, описание в `pyproject.toml`).

## CLI
```
python md-img-local.py <файл.md> [--media каталог] [--no-backup] [--proxy URL] [--lang en|ru] [--write-mode in-place|atomic]
```
- `<файл.md>` — единственный обязательный аргумент.
- `--media` — каталог для картинок, по умолчанию `media/` рядом с файлом.
- Флаг `--no-backup` (опционально) — пропустить создание `.orig`; в режиме `in-place` требует `--force`.
- `--write-mode` (опционально, план; в 1.2.0 не реализован) — способ записи результата: `in-place` (по умолчанию) сохраняет inode, hardlinks, mode/ACL/ADS; `atomic` — атомарная замена через временный файл, но с новым inode.
- `--force` (план) — разрешить перезапись существующего `.orig` и `--no-backup` в `in-place`.
- `--proxy` (опционально) — прокси для скачивания, например `--proxy=socks5://127.0.0.1:3066`; порт обязателен.
- `--lang` (опционально) — язык сообщений и справки: `en` или `ru`; по умолчанию определяется по локали.
- `--version` — вывод версии.

## Алгоритм

1. **Резервная копия**: перед записью результата содержимое `файл.md` копируется в `файл.md.orig` (конвенция уже используется в заметках). Это именно копия, а не `rename`/hardlink, чтобы бэкап был независимым и не делил inode с рабочей заметкой. Существующий `.orig` не перезаписывается молча: ротация (`.orig.1`, `.orig.<timestamp>`) или явный `--force`.

2. **Сбор ссылок** (три синтаксиса):
   - Inline: `![alt](<url> | url "title")`
   - Reference-style: `[id]: <url>` — сначала собрать определения ссылок в словарь, затем находить `![alt][id]` и подставлять URL; `[id]: url` в итоге удаляется из результата.
   - Инлайн-HTML: `<img src="url" ...>` (атрибут `src`, с учётом одинарных/двойных кавычек).

3. **Настройка HTTP-сессии**:
   - Один `requests.Session` на весь запуск (пул соединений, особенно важно через прокси).
   - `User-Agent`, `verify=certifi.where()`, таймаут 30 с.
   - `--proxy`: адрес проверяется до начала работы (схема из `http`, `https`, `socks4`, `socks4a`, `socks5`, `socks5h`; обязательны хост и порт); схема нормализуется в нижний регистр.
   - Для socks-схем проверяется наличие PySocks (`requests[socks]`), иначе понятная ошибка с кодом 2.
   - Прокси задаётся для `http` и `https`; при явном `--proxy` `Session.trust_env = False`, чтобы `HTTP_PROXY`/`HTTPS_PROXY`/`NO_PROXY` не перебивали флаг.
   - В лог прокси попадает с маскированным паролем (`user:***@host`).

4. **Скачивание** в `media/` с дедупликацией:
   - Имя: `stem-<sha256(url)[:10]><ext>` (как в `remote images to local-gpt.md`).
   - Расширение: из URL → иначе `Content-Type` → иначе `.bin`.
   - Одинаковый URL в любом из трёх синтаксисов — скачивается один раз (общий кэш URL→путь).

5. **Замена ссылок** на `media/файл` (posix-слэши, путь относительно файла .md):
   - inline: `![alt](media/файл "title")`
   - reference: заменяется на inline `![alt](media/файл)`, определение удаляется
   - `<img src="media/файл">`
   - Локальные пути (`./`, `media/`, файл без схемы) не трогаются.

6. **Обработка ошибок**: сбой скачивания — `[ERROR] url: причина`, ссылка остаётся как была; обработка продолжается. При использовании прокси в сообщение добавляется подсказка `(прокси <адрес> недоступен?)`.

7. **Запись**: результат пишется в исходный `файл.md` (после успешного полного прохода).

   - `--write-mode=in-place` (по умолчанию, план): сохраняет inode рабочего файла, hardlinks, mode/ACL/ADS и File ID на Windows.
     Порядок: открыть существующий файл без `O_TRUNC`, взять advisory lock, подготовить новый контент во временном файле + `fsync`, сделать независимый бэкап, повторно проверить `fstat` (size/mtime/ino), записать байты, `ftruncate`, `fsync`, сверить hash.
     Journal/`.new` хранится до успешной проверки; при наличии journal на старте программа не продолжает молча, а предлагает восстановление.
     Читатели могут увидеть частичное содержимое — осознанный компромисс ради сохранения inode.
   - `--write-mode=atomic`: временный файл в том же каталоге → `fsync` → `shutil.copystat` → `os.replace`. Атомарно и безопасно при сбое, но меняет inode и отвязывает hardlinks.
   - При сбое посреди `in-place` исходник восстанавливается из `.orig`/`.new`. Без бэкапа (`--no-backup --force`) автоматическое восстановление не гарантируется.
   - В stdout — отчёт: найдено/скачано/не удалось, путь результата.

## Локализация

- Каталог сообщений `MESSAGES` в самом скрипте: `en` и `ru`; ключи одинаковые, при отсутствии перевода — откат на английский.
- Язык определяется в порядке: `--lang` → `MD_IMG_LOCAL_LANG` → `LC_ALL`/`LC_MESSAGES`/`LANG`/`LANGUAGE` → локаль ОС (в Windows — `GetUserDefaultUILanguage`) → английский. Неизвестная локаль даёт английский.
- `--lang` считывается предварительно (до полного разбора), чтобы локализовать саму справку; неверное значение отклоняет argparse с кодом 2.
- Переведены: `--help` (включая `usage`/`positional arguments`/`options`/`error` через подклассы `HelpFormatter`/`ArgumentParser`), отчёт, ошибки валидации прокси, подсказка о недоступном прокси.
- Документация: `README.md` — русский, `README-EN-US.md` — английский, со взаимными ссылками; оба описывают одинаковый набор флагов.

## Проверка
- Локальные ссылки не тронуты, дубликаты URL не качаются повторно.
- `--proxy` не влияет на разбор Markdown и замену ссылок.
- Проверены схемы `http`, `socks5`, `socks5h` (HTTP и HTTPS), ошибки валидации (нет порта, неизвестная схема), недоступный прокси, маскирование пароля.
- Проверена локализация: `--lang`, переменные окружения, локаль ОС, одинаковый набор ключей и плейсхолдеров в каталогах, русская и английская справка/отчёт.
- Проверена запись: `in-place` сохраняет `st_ino`/`st_dev`, hardlinks и mode 600; `atomic` меняет inode, но оставляет исходник целым при inject-сбое; ротация `.orig`; обнаружение конкурентной записи; symlink; read-only каталог; `--no-backup --force`.
- Автотесты: `uv run pytest`, покрытие — `uv run pytest --cov` (pytest, pytest-cov в dev-группе).
