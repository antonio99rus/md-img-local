# План и текущее состояние `md-img-local.py`

Версия — 1.2.0. Документ описывает фактическую реализацию после рефакторинга, а не только исходный замысел.

**Язык:** Python 3.10+. **Зависимости:** `requests[socks]`, `truststore`; dev — `pytest`, `pytest-cov`, `tomli` (только для Python 3.10). Пакет не устанавливается (`package = false`), запуск — `python md-img-local.py`.

## CLI

```
python md-img-local.py <файл.md>
    [--media КАТАЛОГ]
    [--no-backup] [--force]
    [--write-mode {in-place,atomic}]
    [--allow-private]
    [--proxy URL]
    [--user-agent STRING]
    [--lang {en,ru}]
    [--verbose]
    [--version] [-h|--help]
```

- `<файл.md>` — единственный обязательный аргумент.
- `--media` — каталог для изображений. По умолчанию `media/` рядом с Markdown-файлом. Относительный путь отсчитывается от каталога Markdown-файла; `~` раскрывается.
- `--no-backup` — не создавать `.orig`. В `in-place` требует `--force`; в `atomic` разрешён без него.
- `--force` — перезаписать существующий `.orig` вместо ротации, разрешить `--no-backup` в `in-place`, отбросить оставшийся журнал.
- `--write-mode` — `in-place` по умолчанию; `atomic` — opt-in.
- `--allow-private` — разрешить приватные, loopback- и link-local адреса.
- `--proxy` — `http`, `https`, `socks4`, `socks4a`, `socks5`, `socks5h`; порт обязателен; явный прокси отключает `HTTP_PROXY`/`HTTPS_PROXY`/`NO_PROXY`.
- `--user-agent` — по умолчанию `md-img-local/<VERSION>`.
- `--lang` — `en` или `ru`; предварительный разбор понимает сокращения (`--lan`, `--la`, `--l`), `--lang=ru`, повтор флага и `--`.
- `--verbose` — полные URL в логах; по умолчанию URL маскируются. Управляющие символы нейтрализуются всегда, пароль прокси скрывается всегда.
- `--version` — версия из `VERSION`; тест сверяет её с `pyproject.toml`.

## Алгоритм

1. **Чтение.** Файл читается как байты. `decode_markdown()` определяет BOM (UTF-32 LE/BE, UTF-8, UTF-16 LE/BE), иначе декодирует как UTF-8. Исходные BOM и переводы строк сохраняются при записи.
2. **Защита документа.** Маскируются fenced-блоки, inline-код, HTML-комментарии и экранированный `\!`. Замены не затрагивают эти области.
3. **Сбор ссылок.** Inline (`![alt](url "title")`, `<url>`), reference (`![alt][id]` + `[id]: url`; при дубликате побеждает первое определение, title сохраняется) и HTML: `<img src="...">` с `src` в кавычках или без, `srcset` у `<img>` и `<source>`. Protocol-relative URL (`//host/path`) трактуются как HTTPS.
4. **Канонизация URL.** Удаляется fragment, схема и хост приводятся к нижнему регистру, порты по умолчанию отбрасываются. Query не сортируется. Кэш и хэш имени строятся по каноническому URL, поэтому `#fragment` не создаёт дубликат.
5. **Скачивание.** Для каждого уникального URL: SSRF-проверка, ручной цикл редиректов (не более 5, каждый адрес проверяется заново), `stream=True`, лимит 20 МиБ, allowlist `Content-Type`, запись в `media/` через временный файл и `os.replace`.
6. **Замена.** В Markdown — percent-encoded POSIX-путь относительно каталога `.md`; в HTML атрибут также экранируется; дескрипторы `srcset` (`1x`, `480w`) сохраняются. Неудачная загрузка оставляет исходную ссылку. Использованные reference-определения удаляются, если на них больше нет ссылок.
7. **Бэкап и запись.** Независимая копия `.orig` (с ротацией) и выбранный режим записи.
8. **Отчёт.** В stdout: путь, число уникальных URL, скачано, ошибок.

## HTTP и безопасность загрузки

- `REQUEST_TIMEOUT = (10, 30)` — отдельные connect/read таймауты.
- `Retry`: 2 повтора с backoff, статусы `429/500/502/503/504`, только GET; адаптеры навешены на `http://` и `https://`.
- TLS: `configure_tls()` в `main()` инжектирует `truststore`; `session.verify = True`. `certifi` не используется.
- SSRF: хост резолвится, все адреса проверяются на private/loopback/link-local/reserved/multicast/unspecified; ошибка DNS — отказ. `--allow-private` снимает запрет.
- Редиректы: `allow_redirects=False`, `Location` разбирается вручную, лимит 5, каждая цель проходит SSRF-проверку.
- Контент: `image/png`, `image/jpeg`, `image/jpg`, `image/gif`, `image/webp`, `image/bmp`, `image/tiff`, `image/avif`, `image/x-icon`, `image/vnd.microsoft.icon`. SVG намеренно запрещён как активный контент; неизвестный или пустой тип отклоняется.
- Размер: 20 МиБ; проверяется заявленный `Content-Length` и фактически прочитанное тело.
- Имена: `stem-<sha256(canonical)[:16]><ext>`; stem очищается, обрезается до 80 символов, зарезервированные имена Windows получают суффикс; расширение — из фиксированной таблицы `Content-Type`.
- Логи: по умолчанию `mask_url()` скрывает userinfo и чувствительные query-параметры и ограничивает длину; с `--verbose` URL печатается полностью. `sanitize_text()` заменяет управляющие символы в обоих режимах. Прокси печатается с `***` вместо пароля всегда.
- Симлинки: запись идёт через уникальный временный файл в `media/` и `os.replace`, поэтому существующая ссылка заменяется, а не используется как цель записи.

## Бэкап и режимы записи

- Бэкап — `shutil.copy2` в `файл.md.orig`, не `rename` и не hardlink.
- Существующий `.orig` ротируется в первый свободный `.orig.N`; с `--force` перезаписывается.
- `in-place`:
  - открытие без `O_TRUNC` (`O_BINARY` на Windows), advisory lock;
  - снимок `fstat` (`st_dev`, `st_ino`, `st_size`, `st_mtime_ns`);
  - журнал и промежуточная копия в скрытых sidecar-файлах, `fsync`;
  - повторная проверка снимка — при конкурентном изменении запись не выполняется;
  - запись, `ftruncate`, `fsync`, проверка SHA-256;
  - при несовпадении или ошибке — восстановление из `.orig`; без бэкапа восстановление невозможно.
- `atomic`: временный файл в том же каталоге → `fsync` → `shutil.copystat` → `os.replace`. Атомарно, но меняет inode и отвязывает hardlinks.
- Успешный запуск оставляет `.orig` на месте.

## Вывод и коды возврата

- `[OK]`, `[BACKUP]`, `[PROXY]` и итог — stdout; `[ERROR]` и ошибки конфигурации — stderr.
- `0` — успех; `1` — были ошибки скачивания/сохранения; `2` — конфигурация, входные данные или локальный I/O.
- `configure_output()` переключает stdout/stderr в UTF-8 с `errors="replace"` при перенаправлении.

## Локализация

- Каталог `MESSAGES` (`en`, `ru`), одинаковый набор ключей и плейсхолдеров; при отсутствии перевода — откат на английский.
- Язык хранится в `ContextVar`, поэтому потоки не влияют друг на друга.
- Порядок: `--lang` → `MD_IMG_LOCAL_LANG` → `LC_ALL`/`LC_MESSAGES`/`LANG`/`LANGUAGE` → локаль ОС (в Windows — UI language) → английский.
- Переведены справка, `usage`/`positional arguments`/`options`/`error`, типовые ошибки argparse (`required`, `unrecognized arguments`, `invalid choice`, `expected one argument`), отчёт и ошибки загрузки.
- Документация: `README.md` — русский, `README-EN-US.md` — английский, со взаимными ссылками; тест требует, чтобы оба README описывали ровно те же длинные флаги, что и `build_parser()`, и упоминали все runtime-зависимости.

## Тесты

- `uv run pytest` — полный suite; `uv run pytest --cov` — покрытие.
- Тесты герметичны: autouse-фикстура подменяет DNS (литералы как есть, имена → публичный IP), язык фиксируется на английском.
- Есть регрессии на код/комментарии, пробелы и спецсимволы в путях, BOM/CRLF/LF, protocol-relative URL, `src` без кавычек, `srcset`/`<source srcset>`, первое определение reference и сохранение title, лимиты и типы, SSRF, маскирование секретов и `--verbose`, TLS с самоподписанным сертификатом, коды возврата, режимы записи, симлинки, ротацию бэкапов, локализацию и реальную сборку сессии.
- `Socks5Proxy` отслеживает сокеты и потоки и закрывает их в teardown; недоступный прокси проверяется на занятом порту без TOCTOU.
- Текущее состояние: все тесты зелёные; один strict-xfail (indented code) и два skip, зависящих от платформы (POSIX-права, symlink на Windows).
